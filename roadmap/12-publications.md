# 12. Публикации

**Цель:** автор публикует снимок набора по ссылке, выпускает новые версии; другие ставят лайк, подписываются и
делают форк.

Связь с решениями: 2.4 (публикация = снимок).

## Шаги

0. Контракт `proto/flippo/publications/v1/`: публикация, версии, лайки, подписки, форк, лента подписок.
   Публичная страница (шаг 3) — не RPC, а обычная HTML-страница, которую отдаёт сервер или веб-клиент.
1. Модель: `publication { setId, version, snapshot, createdAt }`, `like`, `subscription`, у набора-форка —
   `forkedFrom { publicationId, version }`.
2. Публикация: сервер делает снимок текущего состояния набора из проекций и документов Yjs (карточки + вложения) и
   сохраняет как неизменяемую версию. Вложения копируются или помечаются как используемые снимком, чтобы удаление
   в рабочем наборе их не ломало.
3. Публичная страница по ссылке (в вебе без входа можно смотреть, для лайка и форка — вход).
4. «Опубликовать новую версию»: diff со старой версией (сколько карточек добавлено/изменено/удалено) перед
   подтверждением.
5. Подписчики видят «вышла версия N» (уведомление).
6. Форк: новый набор пользователя с новыми ID карточек, ссылка на версию-источник.
7. Решить открытый вопрос «можно ли публиковать целую папку» и записать в решения.
8. Профиль `flippo.ru/<username>` со списком публикаций.

## Готово, когда

- [ ] Изменения рабочего набора не меняют опубликованную версию.
- [ ] Форк независим от источника; удаление источника форк не ломает.
- [ ] Публичная страница открывается без входа и не раскрывает участников и рабочие данные набора.
