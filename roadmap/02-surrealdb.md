# 02. SurrealDB

**Цель:** ты понимаешь модель данных SurrealDB, пишешь SurrealQL и подключаешь базу к Go-серверу.

Связь с решениями: раздел 4 (серверная и локальная база), 5.1 (модель данных).

## Что изучить

- Документация SurrealDB: <https://surrealdb.com/docs> — разделы про SurrealQL, `DEFINE TABLE/FIELD/INDEX`,
  record ID, связи `RELATE` и графовые запросы, полнотекстовый поиск (`DEFINE ANALYZER`), права (`PERMISSIONS`).
- Go SDK: <https://github.com/surrealdb/surrealdb.go>.

**Проверь версию.** Синтаксис полнотекстовых индексов и часть SDK менялись между мажорными версиями. Смотри
документацию той версии, которую ставишь.

## Шаги

1. Добавь SurrealDB в `docker-compose.yml` (хранилище на томе, логин/пароль из переменных окружения).
2. В `surreal sql` вручную, без кода:
   - создай таблицы `user`, `folder`, `set`, `card` со схемой (`SCHEMAFULL`) по разделу 5.1 решений;
   - заполни несколько записей;
   - сделай связь «набор в папке» двумя способами: полем-ссылкой и `RELATE`. Запиши в заметки, чем они отличаются
     и что выберешь;
   - напиши запрос «все карточки набора, отсортированные по порядку», «наборы папки с количеством карточек».
3. Полнотекстовый поиск с русской морфологией: анализатор с фильтром `snowball(russian)`, индекс по полям
   карточки. Проверь, что запрос «закон» находит «Законы» и «закона». **Это вход для P1**: запиши результат в
   `roadmap/results/surrealdb-fts.md`.
4. Миграции: папка `server/migrations/` с файлами `.surql` по номерам и маленький код в Go, который применяет
   ещё не применённые миграции при старте (храни номер последней в отдельной таблице). Напиши сам — это хорошее
   упражнение.
5. Подключи Go SDK: пакет `internal/store` с интерфейсом репозитория, например
   `SetRepository{ Create, Get, ListByFolder }`, и реализацией на SurrealDB.
6. Интеграционные тесты репозитория против настоящей SurrealDB (поднимай её в Docker или запускай в памяти:
   `surreal start memory`).

## Готово, когда

- [ ] Схема из миграций применяется на чистой базе автоматически.
- [ ] Репозиторий наборов покрыт интеграционными тестами.
- [ ] Записан результат проверки русского полнотекстового поиска.
- [ ] Ты можешь объяснить: record ID, `RELATE` против поля-ссылки, `SCHEMAFULL`, как работает анализатор.

## Ловушки

- Не протаскивай типы SDK (`RecordID` и т. п.) в доменные структуры, как в старом проекте. Домен знает только
  строковые ID; преобразование — внутри `internal/store`.
