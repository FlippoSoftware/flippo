# Flippo: учебный роадмап

Пошаговый план, по которому ты сам пишешь новый Flippo и по пути учишь Go, Rust, Tauri, CodeMirror, Yjs и
криптографию. Каждый этап — отдельный файл. Его можно целиком отдать агенту, если застрянешь.

Источник требований и решений — [../ARCHITECTURE_DECISIONS.md](../ARCHITECTURE_DECISIONS.md). Если роадмап и
решения расходятся, верны решения; роадмап нужно поправить.

## Как пользоваться

1. Иди по этапам по порядку (схема ниже). Внутри этапа шаги тоже по порядку.
2. Сначала прочитай раздел «Что изучить». Не читай документацию целиком: открой, пройди примеры, вернись к шагам.
3. Делай шаг сам. Застрял больше чем на час — спроси агента по шаблону ниже, начиная с самого слабого уровня
   помощи.
4. Этап закрыт, когда выполнены все пункты «Готово, когда». Отметь его в чеклисте ниже.
5. Результаты прототипов (цифры, выводы) записывай в `roadmap/results/`. По ним принимаются решения о стеке.

Прототипы (P1–P5) — **черновой код** в `prototypes/`. Его не нужно делать красиво, его задача — ответить на вопрос.
Основной код пишется заново в `apps/`, `packages/`, `server/`, `collab/`.

## Уровни помощи от агента

Чем ниже уровень, тем больше ты учишься. Поднимайся только если нижний не помог.

| Уровень | Что просишь | Когда |
|---|---|---|
| 1. Объясни | Объяснить понятие или чужой пример, без кода для моей задачи | Не понимаешь, что читаешь в документации |
| 2. Подскажи | Указать направление: какой API, какая идея, где ошибка — без готового решения | Понимаешь задачу, но не знаешь, как подступиться |
| 3. Проверь | Ревью твоего кода: ошибки, идиоматичность, что улучшить | Код работает или почти работает |
| 4. Покажи | Написать минимальный пример, который ты потом перепишешь своими словами | Уровни 1–3 не помогли |
| 5. Сделай | Выполнить шаг целиком | Шаг не учебный для тебя (настройка, рутина) или сроки горят |

### Шаблон запроса агенту

```text
Я прохожу роадмап Flippo, файл roadmap/<этап>.md, шаг <номер>.
Цель: учусь сам. Уровень помощи: <1–5>. Не давай больше, чем этот уровень.

Что я сделал: <коротко, + путь к коду>
Что ожидал: <…>
Что получилось: <ошибка / поведение>
Что уже пробовал: <…>
```

## Правила, которые действуют на всех этапах

- Тесты пишешь вместе с кодом: Go — `go test`, TypeScript — Vitest, Rust — `cargo test`. Ориентир — «каждое правило
  из ARCHITECTURE_DECISIONS проверено хотя бы одним тестом».
- Коммить маленькими шагами с осмысленными сообщениями. Ветка на этап.
- Клиент и сервер общаются через Connect RPC: сначала меняешь контракт в `proto/`, потом генерируешь код и
  реализуешь. Обычный HTTP — только исключения из раздела 6.2 решений.
- Перед тем как взять библиотеку, проверь в её документации текущую версию и API. Примеры в роадмапе — ориентир,
  API могли измениться.
- Записывай, что узнал, в `roadmap/notes/<тема>.md` своими словами. Это лучший способ усвоить материал, и потом
  эти заметки можно будет открыть в самом Flippo.
