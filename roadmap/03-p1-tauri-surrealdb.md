# 03. Прототип P1: Tauri 2 + встроенная SurrealDB

**Цель:** ответить на вопрос «остаётся ли SurrealDB локальной базой на каждой платформе». По пути — освоить
основы Rust и Tauri.

Связь с решениями: раздел 4 (оболочка, локальная база), раздел 7 (P1).

## Что изучить

1. **Rust Book**, главы 1–10 и 13: <https://doc.rust-lang.org/book/>. Ключевое: владение и заимствование,
   `struct`/`enum`/`match`, `Result` и оператор `?`, трейты, замыкания. Дополнительно: Rustlings
   (<https://github.com/rust-lang/rustlings>) — короткие упражнения.
2. Асинхронность в Rust на уровне «как пользоваться»: <https://tokio.rs/tokio/tutorial> (первые разделы).
3. Tauri 2: <https://v2.tauri.app/start/> — создание проекта, **Calling Rust from the frontend** (команды),
   состояние приложения (`State`), события, мобильная разработка.
4. Встраивание SurrealDB в Rust: <https://surrealdb.com/docs/sdk/rust> — embedded-режим с движком SurrealKV.
5. SurrealDB в браузере (WASM): раздел JavaScript SDK про embedded engines.

## Шаги

1. Пройди Rust Book (главы выше) и Rustlings до раздела про ошибки. Выводы — в `roadmap/notes/rust.md`.
2. `prototypes/p1-tauri-surreal/`: создай Tauri 2 приложение с React + TypeScript + Vite.
3. Rust-сторона:
   - открой встроенную SurrealDB с SurrealKV в папке данных приложения (путь получи через API путей Tauri);
   - держи соединение в `tauri::State`;
   - команды: `seed_notes(count)`, `search(query)`, `due_today()`, `stats()`.
4. Данные для теста: сгенерируй 5 000 «заметок» (заголовок + 200–2 000 слов русского текста; возьми любой
   открытый корпус или собери текст из Википедии) и 20 000 «карточек» с полем `due` (дата повторения).
5. Полнотекстовый индекс с `snowball(russian)` по заметкам; индекс по `due` у карточек.
6. Фронтенд: поле поиска, список результатов, кнопка «что повторить сегодня», вывод времени каждого запроса.
7. Веб-вариант: то же самое на SurrealDB WASM + IndexedDB в обычном браузере (отдельная страница или режим сборки).
   Код фронтенда обращается к базе через один интерфейс `LocalDb` с двумя реализациями: `TauriDb` (вызовы команд)
   и `WasmDb`. Так ты сразу отрабатываешь `platform-contracts` из решений.
8. Собери и запусти: Linux (WSL), Windows, Android, iOS (на Mac или в CI), браузер.
9. Замерь на каждой платформе и запиши в `roadmap/results/p1.md` по шаблону ниже.
10. Если на какой-то платформе SurrealDB не работает или цифры плохие — на этой платформе сделай вторую реализацию
    `LocalDb` на SQLite (FTS5) и сравни на тех же данных. Учти: у SQLite FTS5 нет встроенного русского стеммера.

### Шаблон результатов

```markdown
| Платформа | Устройство | Сборка, МБ | Холодный старт, мс | Память в покое, МБ | Поиск, мс (p50/p95) | due_today, мс | Русская морфология | Проблемы |
```

Перед замерами впиши в `results/p1.md` пороги, с которыми согласен (например, «поиск < 100 мс на слабом
телефоне»). Решение принимается по ним, а не по ощущениям.

## Ловушки

- Первая сборка Rust с SurrealDB долгая (много зависимостей). Это нормально; повторные быстрее.
- Не передавай через IPC тысячи мелких вызовов: одна команда — один осмысленный пакет данных.
- В браузере IndexedDB и в Tauri — разные базы. В прототипе это ожидаемо; главное, чтобы интерфейс `LocalDb` был
  одинаковым.
